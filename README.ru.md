# KEYPLO API для продавцов

[English](README.md) · [OpenAPI](openapi.json) · [Центр интеграций](https://keyplo.com/panel/?view=integrations&lang=ru)

Закрытый бизнес-кабинет для продавцов цифровых товаров. Аккаунты создаются лично KEYPLO.

## Текущий статус

API аккаунта доступен. Каталог поставщика, покупки, пополнение/сверка и проверка покупок площадок **пока не подключены**. Каталог возвращает пустой список. Корректный POST заказа возвращает `503 PURCHASING_NOT_ENABLED`: заказ не создаётся, деньги не списываются. Здесь опубликованы только документация и примеры, а не приватный сервер или готовый коннектор выдачи.

## Начало работы

1. Откройте **Интеграции** в своём кабинете.
2. Создайте ключ API, подтвердив пароль и Authenticator (если включён).
3. Сразу сохраните ключ в хранилище секретов сервера: он показывается один раз. Замена аннулирует старый ключ; отзыв сразу блокирует запросы.
4. Задайте на сервере переменную окружения `KEYPLO_API_KEY`.
5. Проверьте `GET https://keyplo.com/api/v1/me` и `/balance`.

```sh
curl 'https://keyplo.com/api/v1/me' -H "Authorization: Bearer $KEYPLO_API_KEY"
```

Не публикуйте настоящий ключ в GitHub, браузерном/мобильном коде или ссылке выдачи. Авторизация только заголовком Bearer по HTTPS. Cookie и ключи в URL не поддерживаются. При блокировке аккаунта ключ и страница выдачи недоступны.

## Методы

| Метод | Путь | Результат сейчас |
| --- | --- | --- |
| GET | /me | Свой аккаунт и доступные возможности |
| GET | /balance | Баланс USD: целое `balance_minor` (центы) и строка `balance` |
| GET | /products | Пустой список, `catalog_connected: false` |
| GET | /orders | Свои заказы; `limit=1..100`, `offset=0..100000` |
| GET | /orders/{id} | Свой заказ; для чужого или отсутствующего — 404 |
| POST | /orders | Проверка контракта, затем 503 без покупки |

POST требует JSON до 16 КБ, `Idempotency-Key` из 16–100 букв/цифр/дефисов/подчёркиваний и `product_id`, `external_id`, `quantity: 1`, `fields: {}`. Заголовок проверяется, но идемпотентное исполнение и учёт **не реализованы**; их нужно подключить до включения покупок.

```json
{"product_id":"PRODUCT_ID","external_id":"YOUR_ORDER_ID","quantity":1,"fields":{}}
```

## Выдача и площадки

В разделе **Интеграции** каждому продавцу доступна постоянная личная ссылка. Владелец KEYPLO видит ссылки в разделе **Продавцы**. Страница принимает ID заказа площадки, но сейчас возвращает недоступность сервиса: проверка покупки не подключена. Ввод ID и наличие ссылки не доказывают оплату и не раскрывают чужие заказы или коды.

Для GGsel, Digiseller и FunPay ещё нужны отдельные адаптеры: защищённое хранение данных площадки, проверка покупки, сопоставление товаров, защита от повторной выдачи и исполнение. Одна ссылка не является готовой интеграцией.

## Ошибки и лимиты

Ответ ошибки содержит `error.code`, `error.message`, `request_id`; ID также в `X-Request-Id`. Для ошибок на русском добавьте `?lang=ru`. Лимиты: 120 запросов/мин на ключ аккаунта и 240/мин на IP. При 429 ждите `Retry-After: 60`. Для проверки выдачи отдельно 12 запросов/мин на IP. Используйте задержку при 429/503. Будущую покупку нельзя повторять с новым idempotency key.

Коды: 400 неверный запрос; 401 неверный/отозванный ключ; 404 ресурс отсутствует/недоступен; 405 метод; 413 большое тело; 415 нужен JSON; 422 неверный заказ; 429 лимит; 503 покупки отключены/сервис недоступен.
